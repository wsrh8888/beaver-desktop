# 消息连接方案

桌面只有一条 WebSocket。不使用 SSE。

这条连接在主进程里。私聊、群聊、个人 Agent、本机工具，都从这里收发。主进程按消息类型和 `conversationId` 分发，窗口只显示。

聊天记录只有一份。服务端先写入原来的会话，再推给这条连接。私聊和群是不同的 `conversationId`，不是不同的连接。

## 个人 Agent

个人 Agent 是当前登录用户的助手，贯穿整个 IM。AI 窗口、某个私聊、某个群、侧边栏或其他模块，都是入口，用的是同一场助手。

窗口把要说的话交给主进程，可以带上当前会话或当前模块。主进程通过这条 WebSocket 发给服务端。服务端要读文件、写文件、执行命令时，把动作推回这条连接。主进程在本机做完，再沿同一条连接把结果送回去。渲染进程不接收工具动作，也不把结果 POST 回去。

窗口关掉，连接还在主进程里，这一轮继续。

助手要看某次私聊或某个群，读已经存好的那份记录。不把群消息的序号和助手的思考写成同一个会话。在群里用它，是看着这个群帮忙，不是把这个群变成助手自己的会话。

## 主进程怎么分

| 进来的是什么 | 主进程做什么 |
| --- | --- |
| 普通私聊、群消息 | 交给对应会话窗口 |
| 任意地方叫助手 | 带着那个 `conversationId` 或模块上下文，跑个人 Agent |
| 本机工具动作 | 主进程执行，结果从这条 WebSocket 回给服务端 |
| 文字增量、工具卡片、结束 | 推给正在看这场助手的窗口 |

## 机器人

别人私聊机器人，或在群里艾特，消息先写入那个私聊或那个群。一个机器人可以同时在很多私聊和很多群里，这些都是 `conversationId`。

回复写回原来的会话。用户的桌面从自己这条 WebSocket 看见，和普通聊天一样。

机器人的脑子放在哪，只影响谁来生成这句回复：

- 放在这台桌面的主进程：不另开连接。消息从用户这条 WebSocket 下来，主进程生成回复并写回原会话。桌面不在线就不会回。
- 放在桌面外面的龙虾进程：那个进程自己连开放平台 `GET /api/open/ws/v1/connect`，或走 Webhook。身份是应用，不是登录用户。一根连接上挂着它参与的全部私聊和群。流式增量不落库；终稿用开放平台 `send_message` 落库，再推到成员的用户连接。

同一个机器人只留一个脑子。开放平台连接和桌面主进程不要同时处理同一次艾特。
